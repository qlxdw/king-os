## 3. 从上电到 C 内核

### 3.1 BIOS、MBR 与 Loader

传统 BIOS 从启动盘第一个扇区读取 512 字节到物理地址 `0x7c00` 并跳转执行。`boot/mbr.S` 受一个扇区限制，主要设置段寄存器和栈，通过 ATA PIO 从固定 LBA 读取 Loader，再跳转过去。

`boot/loader.S` 空间更充足，负责：

```text
获取物理内存信息
 -> 建立 GDT
 -> 打开 A20
 -> 设置 CR0.PE，进入保护模式
 -> 读取内核 ELF
 -> 建立初始页目录和页表
 -> 设置 CR3，打开 CR0.PG
 -> 按 ELF Program Header 搬运可加载段
 -> 跳转到 0xc0001500 的内核入口
```

### 3.2 保护模式与特权级

保护模式下，段寄存器保存段选择子，选择子指向 GDT/LDT 描述符。项目主要使用 Ring 0 和 Ring 3：

```text
Ring 0：内核、驱动、中断和系统调用处理
Ring 3：用户进程和用户程序
```

GDT 提供代码段、数据段、显存段和后续 TSS 描述符的基础。特权级使用户程序不能直接访问内核内存或执行任意 IO 指令。

### 3.3 高地址内核映射

内核链接地址是 `0xc0001500`。Loader 通过页表把高虚拟地址映射到实际物理内存：

```text
0x00000000 ---------------- 用户空间
             用户代码、数据、堆、栈
0xc0000000 ---------------- 内核空间
             内核代码、数据、堆和固定映射
0xffffffff ----------------
```

进程拥有各自的低 3 GB 用户映射，同时共享高 1 GB 内核映射。这使进程隔离和系统调用进入同一内核成为可能。

### 3.4 ELF 装载

真正指导装载的是 Program Header：

```text
ELF Header：入口地址、程序头表位置和数量
PT_LOAD：段的文件偏移、目标虚拟地址、文件大小和内存大小
```

Loader 只搬运可加载段，不把符号表、节表等所有 ELF 内容原样复制到内存。

## 4. 内核初始化顺序

`kernel/main.c` 调用 `init_all()`：

```text
idt_init()       IDT 和 PIC
mem_init()       内核/用户内存池和页分配
thread_init()    主线程、idle、就绪队列和 PID
timer_init()     PIT 时钟中断
console_init()   控制台互斥封装
keyboard_init()  键盘中断和输入队列
tss_init()       用户态进入内核所需的 esp0
syscall_init()   系统调用表
intr_enable()    开中断
ide_init()       IDE 通道、磁盘和分区扫描
filesys_init()   格式化/挂载自制文件系统
```

顺序存在依赖：线程和同步依赖内存；IDE 使用中断与信号量；文件系统依赖 IDE 和内存分配。

## 5. 中断、时钟与系统调用

### 5.1 中断通路

核心文件是 `kernel/interrupt.c` 和 `kernel/kernel.S`：

```text
设备产生 IRQ
 -> 8259A PIC 仲裁
 -> CPU 查 IDT
 -> 汇编入口保存上下文
 -> C 处理函数处理设备并清状态
 -> PIC EOI
 -> intr_exit 恢复现场并 iretd
```

`intr_exit` 还被用户进程首次启动、fork 子进程恢复和 exec 切换入口复用。

### 5.2 PIT 与抢占调度

`device/timer.c` 配置 PIT 周期中断。每个 tick 更新全局时间和当前任务运行时间；时间片未耗尽则递减，耗尽则进入 `schedule()`。这形成基本的抢占式时间片轮转。

### 5.3 系统调用入口

用户库把系统调用号和参数放入约定寄存器，触发软件中断。`syscall_handler` 保存现场，根据 `userprog/syscall-init.c` 的 `syscall_table` 调用内核函数。

当前系统调用覆盖：

```text
进程：getpid、fork、execv、exit、wait、ps
内存：malloc、free
文件：open、close、read、write、lseek、stat、unlink
目录：mkdir、rmdir、opendir、readdir、chdir、getcwd
IPC：pipe、fd_redirect
终端：putchar、clear、help
```

系统调用边界还应承担用户指针和长度校验；本项目已实现调用通路，但参数安全检查较简化。

## 6. 线程、调度与同步

### 6.1 PCB 与内核栈

每个任务使用一个 4 KB 页，低地址存放 `task_struct`，其余空间作为向下增长的内核栈。`self_kstack` 记录栈位置；ESP 按页对齐后可快速定位当前 PCB。

```text
thread_ready_list：可以运行、等待 CPU 的任务
thread_all_list：系统全部任务，用于查询和 ps
```

### 6.2 上下文切换

`thread/switch.S` 保存当前任务的 `esi、edi、ebx、ebp、esp`，加载下一任务 ESP，再恢复寄存器并返回。首次任务栈必须伪造成与该恢复顺序完全一致的结构。

任务阻塞时修改状态并调用调度器；唤醒时改回 READY 并加入就绪队列。IDE、键盘队列、信号量和 wait 都复用该机制。

### 6.3 信号量与锁

`sema_down()` 在资源不可用时把当前任务加入等待队列并阻塞，`sema_up()` 唤醒一个等待者。单核环境通过保存中断状态、关闭中断、修改共享数据、恢复中断保证原子性。

锁在二元信号量上增加持有者与重复持有次数，所以同一任务可重复获取。这里的可重入不等于代码可被任意中断安全重入。

## 7. 内存管理

### 7.1 虚拟地址、物理页和映射

页分配要管理三种资源：

```text
vaddr_get()             在虚拟地址位图找连续范围
 -> palloc()            逐页申请物理页
 -> page_table_add()    建立 PDE/PTE 映射
```

虚拟地址可以连续，物理页不必连续。物理内存简化地分成 `kernel_pool` 和 `user_pool`，避免用户分配耗尽全部内核资源。

### 7.2 自映射页表

页目录最后一项指向页目录自身：

```text
0xfffff000：页目录窗口
0xffc00000 起：页表窗口
```

`pde_ptr()` 和 `pte_ptr()` 因而能直接计算任意虚拟地址对应表项的位置。

### 7.3 arena 小块分配

项目用 arena 和多规格空闲链表管理 `16~1024` 字节的小块；大于 1024 字节按整页分配，降低小对象占用整页的浪费。

### 7.4 当前边界

- 页分配中途失败时，已经占用的虚拟位、物理页和表项没有完整回滚；
- `get_user_pages()` 应在分配失败后避免对空指针 `memset`；
- 页数量使用 `uint16_t`，最多约 256 MB，若目标是 512 MB 应改用 `uint32_t` 并核对位图容量。

## 8. 用户进程与 TSS

线程和进程共用调度框架。用户进程额外拥有独立页目录、用户虚拟地址位图、Ring 3 段、用户栈和 Ring 0 内核栈。

`process_execute()`：

```text
申请 PCB 页
 -> 初始化任务字段
 -> 创建用户虚拟地址位图
 -> 构造首次调度栈
 -> 创建独立页目录
 -> 初始化用户堆描述符
 -> 加入 ready/all 队列
```

`start_process()` 在内核栈构造 `intr_stack`，填写用户 CS/SS、EIP、ESP 和 EFLAGS，再跳到 `intr_exit`，通过 `iretd` 进入 Ring 3。

项目不使用 TSS 硬件任务切换，主要使用其中的 `esp0`。当 Ring 3 因中断/系统调用进入 Ring 0 时，CPU 用它找到当前进程内核栈。切换进程页表后必须同步更新 `esp0`。

## 9. fork、exec、wait 与 exit

### 9.1 fork

`userprog/fork.c`：

```text
复制 PCB 和内核栈
 -> 复制用户虚拟地址位图
 -> 创建子页目录
 -> 遍历父进程已使用用户页
 -> 借一页内核缓冲逐页复制到子地址空间
 -> 调整子栈，使 eax=0
 -> 更新文件/inode/管道引用
 -> 加入就绪队列
```

父进程得到子 PID，子进程得到 0。当前是完整复制，不是 COW，代价与父进程已使用内存成正比。

### 9.2 exec

`exec` 不创建新进程，而是替换当前进程用户态内容：

```text
打开并校验 ELF32/i386
 -> 遍历 Program Header
 -> 为 PT_LOAD 段准备用户页
 -> 读取到 p_vaddr
 -> 修改进程名和 intr_stack 的 EIP/ESP
 -> 传递 argc/argv
 -> intr_exit 进入新程序
```

当前主要按 `p_filesz` 加载，尚未完整处理 `p_memsz > p_filesz` 的 BSS 清零、段权限和严格用户地址边界。

### 9.3 exit、wait 与 init

子进程退出时释放用户空间资源，保存退出状态并进入 `TASK_HANGING`，父进程仍需通过 `wait()` 回收 PCB/PID。有存活子进程但没有僵尸时，父进程阻塞；没有任何子进程则返回 `-1`。

孤儿进程由 PID 1 的 init 收养。`kernel/main.c` 中 init 父分支持续 wait，子分支运行 Shell。

## 10. IDE PIO 驱动

核心文件是 `device/ide.c`。

### 10.1 读取流程

```text
获取 IDE 通道锁
 -> 选择主/从盘
 -> 写扇区数量和 LBA28
 -> 下发 READ SECTOR
 -> 当前任务在 disk_done 信号量阻塞
 -> 磁盘产生 IRQ14/IRQ15
 -> 中断处理 sema_up
 -> 检查 BSY/DRQ
 -> insw 从数据端口读取扇区
 -> 释放通道锁
```

写流程类似，但设备准备好后先用 `outsw` 写数据，再等待完成中断。锁保证同一通道同一时刻只有一个请求，信号量让 CPU 在磁盘工作期间运行其他任务。

驱动还会读取 MBR/EBR，扫描主分区和扩展分区链，把结果加入 `partition_list`，供文件系统挂载。

### 10.2 超时表达式问题

源码中：

```c
while (time_limit -= 10 >= 0)
```

关系运算优先级高于复合赋值，它接近于：

```c
time_limit -= (10 >= 0);
```

实际每次减 1，而且 `time_limit` 是无符号类型，可能下溢。正确思路应显式判断剩余时间，再单独递减。这说明底层代码不仅要看算法意图，还必须检查 C 表达式的真实结合方式和整数类型。

## 11. 自制 inode 文件系统

核心文件：

```text
fs/fs.c
fs/inode.c
fs/file.c
fs/dir.c
fs/super_block.h
```

### 11.1 分区布局

```text
第 0 扇区：保留/引导块
第 1 扇区：超级块
后续：块位图
后续：inode 位图
后续：inode 表
后续：数据区
```

超级块记录各区域起始 LBA、扇区数量、inode 总数、根 inode 和目录项大小，是文件系统的总布局说明。

### 11.2 格式化与挂载

`filesys_init()` 遍历分区，读取超级块并检查魔数：

```text
魔数匹配：已有本项目文件系统
魔数不匹配：格式化分区
```

格式化会创建超级块、位图、inode 表和根目录的 `.`/`..`。随后挂载默认 `sdb1`，将超级块、块位图和 inode 位图读入内存。

“未知文件系统就格式化”只适合专用教学磁盘镜像，真实系统必须避免破坏已有数据。

### 11.3 inode、目录项与路径

inode 保存文件大小、编号、打开计数、写互斥标志，以及 12 个直接块地址和 1 个一级间接块表地址。

目录也是文件，其数据块保存：

```text
文件名 + inode 编号 + 文件类型
```

路径 `/a/b/c` 会从根目录开始逐级查找目录项，把名字依次转换为 inode，最终得到目标文件。

### 11.4 文件描述符映射

```text
进程局部 fd
 -> PCB fd_table[]
 -> 全局 file_table[]
 -> inode
```

局部 fd 让每个进程都能使用 0、1、2；全局文件表保存共享打开对象。fork 后父子 fd 可能指向同一个全局项，因此需要维护 inode/管道引用关系。

### 11.5 文件块与最大文件

```text
12 个直接块
128 个一级间接块
合计 140 个 512 字节块
```

最大文件约 70 KB。写入过程需要处理同块追加、分配直接块、跨入一级间接块和已在间接区继续扩展等情况，并同步位图和 inode。

创建文件会依次占用 inode 位、全局文件表项、目录项和磁盘元数据，所以失败时需要按阶段回滚。项目已经体现了回滚思路，但写入过程中磁盘满等失败路径仍可继续加强。

### 11.6 跨块读取问题

源码使用：

```c
uint32_t read_blocks = block_read_start_idx - block_read_end_idx;
```

应表达为结束块减起始块。当前写法在跨块时发生无符号下溢。测试不能只覆盖小文件，还应覆盖：

```text
空文件
511/512/513 字节
跨多个直接块
第 12/13 块边界
文件尾和越界读取
```

## 12. Shell、外部程序与管道

### 12.1 Shell 主循环

```text
打印提示符
 -> 从键盘 IO 队列读取一行
 -> 解析 argc/argv
 -> 内建命令：Shell 自己执行
 -> 外部命令：fork 子进程并 exec
 -> 父 Shell wait
```

`cd` 必须在 Shell 自己执行。如果在子进程中改变工作目录，子进程退出后父 Shell 的目录不会变化。

参数解析当前先写 `argv[argc]`，后检查 `argc > MAX_ARG_NR`，存在越界。检查应放在写数组之前，并使用 `argc >= MAX_ARG_NR`。

### 12.2 `/cat` 如何进入并运行

`command/compile.sh` 把 `cat` 编译成 32 位 ELF，写到磁盘 LBA 300。内核启动时从固定 LBA 读取固定大小，再创建文件系统中的 `/cat`。

执行 `/cat file`：

```text
Shell fork
 -> 子进程 stat /cat
 -> execv 打开 ELF
 -> 加载 PT_LOAD 段
 -> _start 把 argc/argv 传给 main
 -> cat 通过 read/write 系统调用访问文件和终端
 -> exit
 -> 父 Shell wait 回收
```

当前方式硬编码程序 LBA、大小和磁盘路径。更合理的工程方式是由镜像制作阶段根据实际 ELF 大小把用户程序预置进文件系统。

### 12.3 管道和重定向

`sys_pipe()` 用全局文件表项代表管道，把一页内核内存解释为环形 IO 队列，并向进程返回两个局部 fd。

```text
fd_redirect(1, pipe_write_fd)
 -> 前一命令 stdout 写入管道

fd_redirect(0, pipe_read_fd)
 -> 后一命令 stdin 从管道读取
```

核心不是 Shell 手工搬运字符串，而是让标准 fd 指向不同内核对象，从而复用原有 `read/write` 接口。

当前管道在页分配判空前调用 `ioqueue_init()`，并缺少全局/局部 fd 耗尽检查；读写是“尽可能处理当前数据”的简化语义，还没有完整 EOF、断管和阻塞规则。

## 13. 一条完整链：输入 `cat /file`

```text
键盘按键
 -> 键盘 IRQ
 -> keyboard.c 解码扫描码
 -> 字符进入 ioqueue
 -> Shell readline 取字符
 -> cmd_parse 得到 argv
 -> 判断 cat 是外部命令
 -> fork 复制 Shell 进程
 -> 父进程 wait 阻塞
 -> 子进程 execv("/cat", argv)
 -> 文件系统查找 /cat inode
 -> IDE 读取 ELF
 -> exec 映射并装入 PT_LOAD 段
 -> intr_exit 进入 Ring 3
 -> cat open/read 目标文件
 -> 系统调用进入内核
 -> inode 转换为数据块
 -> IDE 读取数据
 -> write(1) 输出控制台
 -> exit 保存退出状态
 -> 唤醒父 Shell
 -> wait 回收子进程
 -> 再次打印提示符
```

Shell 不直接读取 IDE，IDE 不知道文件名。操作系统通过分层把用户意图逐步变成具体硬件操作。

## 14. 构建与调试

### 14.1 工具链

```text
nasm -f elf          汇编 32 位目标文件
gcc-4.4 -m32         编译 freestanding C
ld -m elf_i386       链接 32 位内核
-Ttext 0xc0001500    指定内核链接地址

```

`-fno-builtin` 防止编译器把自制字符串/内存函数替换成宿主 libc 内建实现；`-fno-stack-protector` 避免产生当前内核未提供的栈保护运行库依赖。

### 14.2 磁盘镜像布局

Makefile 用 `dd` 写入：

```text
MBR -> LBA 0
Loader -> LBA 2
kernel.bin -> LBA 9
cat -> LBA 300
```

它便于学习启动布局，但存在路径和大小硬编码、编译与修改磁盘绑定、误写目标等问题。可以拆成 `build`、`image`、`run`、`debug` 目标，并默认生成新的镜像副本。

### 14.3 GDB 断点链

```text
启动：loader_start -> p_mode_start -> enter_kernel -> main
调度：intr_timer_handler -> schedule -> switch_to
系统调用：用户封装 -> syscall_handler -> syscall_table
进程：sys_fork -> sys_execv -> intr_exit -> sys_exit -> sys_wait
文件：sys_open -> search_file -> file_read -> ide_read
```

结合 `kernel.map`、反汇编、寄存器、CR3 和栈内存观察，可把 C 数据结构与真实 CPU 上下文对应起来。

## 15. 优化优先级

### 第一层：正确性

1. 修正 IDE `busy_wait()` 的表达式优先级和无符号下溢。
